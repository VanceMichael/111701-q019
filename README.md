# 供应商发票录入采集服务

这是一个用于供应商发票录入的本地数据采集与归档服务。当前版本从仓库自带的合成来源记录读取一页数据，经过字段规整后写入进程内目录；来源内容和规整后的记录保留独立边界，便于在不访问外部系统的情况下复现采集过程。

## 运行

需要 Node.js 20 或更高版本，不需要安装第三方依赖。

```sh
npm test
npm run build
node src/pipeline.mjs
```

测试使用项目内的合成记录；执行不需要网络、凭据或外部服务。

## 录入超时后的对账

`src/reconcile.mjs` 按「发票 + 录入批次」把本地待办与门户回执对账。门户超时不能证明远端失败：发票可能已经进入审核队列，直接重试会制造重复审核，直接标记失败又可能漏账。

规则：

- 有受理类回执（如 `queued`、`审核中`、`duplicate`）→ `accepted`。
- 只有明确的拒绝类回执（如 `rejected`、`校验失败`）→ `rejected`。
- 无回执、只有超时回执、回执状态未知、受理与拒绝回执冲突、回执不完整 → `needsVerification`（待人工核实队列），既不能标成功，也不能当失败重试。
- 受理与拒绝回执同时存在时不猜哪条更新，一律进入待核实队列。
- 同一发票 + 批次的多条本地重试记录合并为一项对账，并给出稳定的 `idempotencyKey`，便于重试前先查远端结果。
- 无法归属到本地待办的回执进入 `unmatchedReceipts`，不会被静默丢弃。

调用方应在 `needsVerification` 清空之前暂停该发票的自动重试和自动入账。
